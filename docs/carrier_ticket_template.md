```
- dumpsys telephony.registry (telephony.txt)
- dumpsys ims (ims.txt)
- Screenshot: Settings → Mobile network → SIM status
- Screenshot: ##4636## → Phone info (include PLMN, Service state, RSRP/RSRQ/SINR if shown)

Requested actions (apply in order):

1. Verify subscription status in OSS/BSS: ensure `subscriberStatus == ACTIVE` and no barring applied.
2. Confirm ICCID ⇄ IMSI mapping in provisioning DB matches supplied values; correct if mismatched.
3. Force UpdateLocation for IMSI (S6a / MAP UpdateLocation) to refresh HLR/HSS binding and visited network entries.
4. Re-push InsertSubscriberData / SubscriberData if needed to ensure MMTEL/IMS bindings are present.
5. Trigger IMS re-registration / SIP REGISTER retry for the IMSI (inspect SIP reg logs; expect 200 OK).
6. Push Carrier Config Update (OTA) or confirm APN/IMS/VoLTE fields on the subscription: provide exact APN values if re-provision is not possible.
7. Confirm final registration: PLMN registration, IMS REGISTER success, and data PDP/PDN attach (attach logs or trace id).

Expected result:

Device registers on PLMN, IMS REGISTER completes, and cellular data & VoLTE restore. Provide timestamps/log snippets of successful attachments and SIP 200 OK for the final confirmation.
If you cannot re-provision from OSS/HSS, please escalate to provisioning/network operations and include trace IDs for the attempted attach and SIP registration.
```

Use this verbatim in carrier/provisioning escalations and attach the diagnostic bundle generated by the toolkit.
